# LAN Sync - Obsidian 局域网同步插件

一款类似 LocalSend 的 Obsidian 插件，支持在局域网内不同设备间自动同步 Obsidian 仓库、绑定设备关系、分享笔记。

## 功能特性

### 设备发现与身份

- 插件启动时自动为当前设备生成唯一 ID 和中文别名（如"快乐的书签"）
- 别名可自定义修改，局域网内保持唯一
- **桌面端**：通过 UDP 广播自动发现局域网内的其他设备（即插即用）
- **移动端**：手动输入桌面设备 IP 地址进行连接

### 设备绑定

- 在设备列表中点击目标设备的别名，发起绑定请求
- 发起方屏幕显示 6 位验证码，目标方输入验证码完成验证
- 验证码校验通过后自动建立绑定关系，当前仓库纳入同步范围
- 同一设备可参与多个绑定组，每个绑定组包含 2 台设备

### 自动同步

- 后台服务按配置的间隔（默认 15 分钟）检查绑定设备的仓库变更
- 对比各设备文件清单，以拥有最晚修改时间的设备数据为准
- 增量同步差异文件到其他在线设备
- 同步前自动为本地文件创建历史副本（默认保留 5 份）
- 文件的删除操作也会同步到其他绑定设备

### 解绑设备

- 在设置页面的已绑定设备列表中可随时解除绑定
- 解绑后双方不再自动同步，但各自仓库文件不受影响
- 解绑时会通知对方设备，确保双方状态一致

### 传输安全与效率

- **AES-256-GCM 加密**：所有文件传输内容自动加密，接收端自动解密
  - 密钥在设备绑定时从绑定组 ID 和设备 ID 派生，双方持有相同密钥
  - 每次加密使用随机 IV，确保相同内容加密结果不同
  - 数据格式：`base64(iv + authTag + ciphertext)`，自带完整性校验
- **大文件分片传输**：超过 10MB 的文件自动切分为多个分片逐片传输
  - 每个分片独立加密，避免移动端大文件传输 OOM
  - 分片会话管理：`init` → `chunk` × N → `complete` 三步完成
  - 分片大小可在设置中配置（默认 10MB）

### 实时通信（WebSocket）

- 桌面端运行 WebSocket Server，挂载在 HTTP Server 的 `/ws` 路径
- 其他设备通过 WebSocket Client 保持长连接，替代 HTTP 轮询
- 支持实时同步触发通知、设备在线状态即时更新
- 客户端自动重连（指数退避，最大 30 秒）+ 心跳保活（每 15 秒）

### 同步历史

- 记录每次同步的详细信息，包括发送/接收的文件列表及变更类型（新增/修改/删除）
- 同步历史独立存储在 `sync-history.json`，不影响主设置文件
- 设置页面内联预览最近记录，可弹窗查看详情
- 与 Obsidian File Recovery 互补，提供精确的同步前快照

### 历史副本管理

- 文件被同步覆盖前，自动在隐藏目录 `.obsidian/.lan-sync-history/` 创建副本
- 目录结构与仓库一致，命名格式为 `原文件名_YYYYMMDD_HHmmss.md`
- 自动清理超出数量限制的旧副本

### 状态栏（桌面端）

- 桌面端 Obsidian 底部状态栏显示同步状态图标
- 点击弹出快捷菜单：手动同步、查看设备、打开设置等

### 多语言支持

- 支持 6 种语言：简体中文、English、繁体中文、Français、日本語、한국어
- 根据 Obsidian 语言设置自动切换
- 设备别名支持按语言生成随机中文风格名称

### 笔记分享

- 在笔记文件右键菜单中选择「分享到设备...」
- 目标设备弹窗确认（拒绝 / 接收 / 另存为 / 加入黑名单）
- 连续拒绝同一设备分享请求达到阈值（默认 3 次）后自动拉黑
- 设置页面可管理黑名单

### 文件缓存

- 基于文件 MD5 哈希的增量缓存，避免重复计算
- 支持增量刷新（仅更新变更文件）和全量刷新（清空重算）
- 缓存记录存储在设置中，插件重载时自动恢复

## 使用方法

### 安装

1. 将以下文件复制到 Obsidian 仓库的 `.obsidian/plugins/lan-sync/` 目录：
   - `main.js`
   - `manifest.json`
   - `styles.css`
2. 打开 Obsidian → 设置 → 第三方插件 → 启用 "LAN Sync"

### 基本使用

1. **配置设备别名**：设置 → 设备信息 → 设备别名（建议设置有辨识度的名称）
2. **确保可被发现**：勾选「可被发现」开关
3. **发现设备**：命令面板搜索「查看局域网设备」或在设置页面点击「查看设备」
4. **绑定设备**：在设备列表中点击目标设备的「绑定」按钮，按提示输入验证码
5. **自动同步**：绑定完成后，插件会按设定间隔自动同步仓库内容

### 命令

| 命令 | 说明 |
|------|------|
| 查看局域网设备 | 浏览并绑定局域网内的其他设备 |
| 立即同步 | 手动触发一次仓库同步 |

### 设置项

| 设置 | 默认值 | 说明 |
|------|--------|------|
| 同步间隔 | 15 分钟 | 自动同步的时间间隔 |
| 历史副本数量 | 5 | 每个文件保留的历史副本数 |
| 历史副本目录 | `.obsidian/.lan-sync-history` | 历史副本保存路径 |
| 自动拉黑阈值 | 3 次 | 连续拒绝分享后自动拉黑 |
| 分片大小 | 10MB | 大文件分片传输的每片大小 |

## 平台支持

| 功能 | 桌面端 (Win/Mac/Linux) | 移动端 (Android/iOS) |
|------|:---:|:---:|
| 自动发现设备 | ✅ | ❌ |
| 手动连接设备 | ✅ | ✅ |
| 运行 HTTP 服务 | ✅ | ❌ |
| 接收/发送同步 | ✅ | ✅ |
| 分享笔记 | ✅ | ✅ |
| 接收分享确认 | ✅ | ✅ |

> 移动端由于 WebView 限制，无法运行 UDP 广播和 HTTP Server，需手动输入桌面设备 IP 地址。移动端之间的直接同步不可行，需通过桌面设备中转。

## 开发

### 环境要求

- Node.js >= 18
- npm

### 安装依赖

```bash
npm install
```

### 开发模式（watch）

```bash
npm run dev
```

文件修改后会自动重新编译，在 Obsidian 中重新加载插件即可生效。

### 生产构建

```bash
npm run build
```

编译产物为根目录下的 `main.js`。

## 打包发布

### 手动安装

将以下三个文件复制到 `.obsidian/plugins/lan-sync/` 目录：

```
main.js
manifest.json
styles.css
```

### 发布到社区

1. 创建 GitHub 仓库，推送代码
2. 创建 Release，上传 `main.js`、`manifest.json`、`styles.css`
3. 向 [obsidian-releases](https://github.com/obsidianmd/obsidian-releases) 提交 PR

## 网络架构

```
Desktop A (全能力节点)                Desktop B (全能力节点)
+--------------------+               +--------------------+
| UDP Discovery      |  <--UDP广播--> | UDP Discovery      |
| HTTP Server (:24532)|  <--HTTP----> | HTTP Server (:24532)|
| WebSocket Server   |  <--WS----->  | WebSocket Server   |
| Sync Engine        |               | Sync Engine        |
| AES-256-GCM        |               | AES-256-GCM        |
+--------------------+               +--------------------+
         ^                                    ^
         | HTTP + WS (requestUrl)             | HTTP + WS (requestUrl)
         v                                    v
+--------------------+               +--------------------+
| Mobile C (客户端)   |               | Mobile D (客户端)   |
| HTTP/WS Client     |               | HTTP/WS Client     |
| AES-256-GCM        |               | AES-256-GCM        |
+--------------------+               +--------------------+
```

- **设备发现**：UDP 广播 (port 24531)，桌面端自动发现
- **数据传输**：HTTP (port 24532)，RESTful API + 分片上传
- **实时通信**：WebSocket (`/ws`)，长连接替代轮询
- **传输加密**：AES-256-GCM，绑定后自动启用
- **跨平台 HTTP**：统一使用 Obsidian `requestUrl()` 接口
